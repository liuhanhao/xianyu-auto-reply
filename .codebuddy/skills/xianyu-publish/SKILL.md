# 闲鱼商品发布

## 用途

把一份商品配置 YAML 变成闲鱼上已上架的商品。发布走 `xianyu-auto-reply` 的公开接口（`/api/v1/external/publish/*`），只认分销秘钥，不需要登录态，不需要操作客户端界面。

## 前置条件

发布前确认三件事，缺一不可：

1. `backend-web` 服务在运行，默认 `http://127.0.0.1:8089`。用 `curl -s http://127.0.0.1:8089/health` 确认，返回 `success: true` 且 `database: connected` 才算就绪。
2. 目标闲鱼账号已在客户端登录，Cookie 有效。发布是用该账号的 Cookie 直接调闲鱼 mtop 接口，Cookie 失效会报「账号缺少Cookie」。
3. 配置文件里有 `secret_key` 和 `account_id`。

## 工作流

### 1. 准备配置文件

把 `assets/listing.template.yaml` 复制到工作区（建议 `listings/<商品名>.yaml`），让用户填写。

只要求用户提供真正需要人拍板的信息：**价格、图片、所在地、发哪个账号**。标题和描述可由用户口述要点后生成，再给用户确认。

`account_id` 不知道填什么时留空，脚本会列出该秘钥下的全部账号后退出，把清单给用户选。

### 2. 图片

图片是硬门槛：发布接口只接受 `media_id`，不接受本地路径，必须先上传。

- 用户提供本地图片 → 填绝对路径到 `images`
- 用户需要配图 → 先用图片生成能力出图并让用户确认，再把落盘路径填入 `images`

卖二手实物时提醒用户：闲鱼对图文一致性有要求，AI 生成图用于实物商品存在被判虚假描述的风险，实拍更稳妥。虚拟商品、卡券、素材、氛围封面不受此限。

### 3. 先预览再发布

```bash
python3 scripts/publish.py <配置.yaml> --dry-run
```

预览会打印闲鱼返回的分类候选清单和所选分类，不产生任何发布动作。**分类不对是发布后最难撤回的问题，所以不要跳过这一步。**

推荐结果默认取第 1 个。不准时把候选序号填进 `category_index` 后重跑预览。

### 4. 发布

```bash
python3 scripts/publish.py <配置.yaml>
```

成功后输出商品 ID 和链接，把链接回给用户。

## 脚本参数

| 参数 | 作用 |
|------|------|
| `--dry-run` | 只解析配置、推荐分类、上传图片并预览，不发布 |
| `--accounts` | 只列出秘钥下的账号 ID 和备注，用于填 `account_id` |
| `--base-url` | 服务不在默认地址时指定，如 `http://192.168.1.10:8089/api/v1` |

## 失败处理

脚本所有接口错误都会打印 `[code=xxx]` 和中文原因，按原因处理：

| 现象 | 原因与处理 |
|------|-----------|
| `code=40001 秘钥不存在` | `secret_key` 填错，回客户端重新复制 |
| `code=40002` / 账号不存在 | `account_id` 不属于该秘钥，用 `--accounts` 重新查 |
| 账号缺少 Cookie | 客户端里重新登录该闲鱼账号 |
| 分类推荐未返回结果 | 账号 Cookie 已失效，重新登录后重试 |
| 返回 `punish_url` 或提示风控 | 闲鱼触发滑块验证，把链接给用户，在浏览器手动过一次 |
| 无法连接 8089 | 服务没跑，确认客户端或 Docker 容器在运行 |

## 注意

- 一次配置文件只发布一个商品到**一个**账号。多账号发布就准备多份配置，逐份执行。
- 图片上传后绑定到该账号，换账号发布需要重新上传。
- 每次执行都会真实调用闲鱼发布接口，发布前务必核对价格。价格填错只能下架重发。
